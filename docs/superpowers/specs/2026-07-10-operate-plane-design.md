## Overview

This spec merges five Operate-plane track designs (OP1 Workflows move, OP2 Projects AI-PM, OP3 Artifacts, OP4 Runs + scheduler, OP5 Context drill-down) into one ordered, gated build covering operator asks O1–O7.

**Macro order (resequenced for the operator's declared quick-win priority — O4):**
**U1 Workflows move (small first win) → U2–U3 Projects backend v2 + Board/Backlog/Drawer/Timeline/Docs UI (the visible Notion/Asana feel, landing SECOND) → U4 scheduler backend → U5–U6 run index + Runs UI → U7 shared step render → U8 schedules wizard → U9 dashboard → U10–U11 Artifacts → U12 Projects plan-ops/AI depth → U13–U14 Context → U15 gate.**

Dependency audit behind the reorder (verified): the Projects quick-win units consume **nothing new** — the drawer's linked-runs uses existing `GET /api/workflows/runs/{run_id}`, Docs uses existing `/api/workspaces` routes, and the UI unit deliberately avoids LibraryShell. The scheduler chain does not consume Projects. Scheduler (U4) lands before Artifacts (U10–U11) so the Workspaces-pane schedule relations and prefilled wizard have a real backend. Only U12 has soft cross-track dependencies (master-key transport for proposal accepts) and stays late.

Three overlap resolutions are binding across every unit:

1. **ONE shared per-step render core** — `api/static/js/runs/step-log-render.js`. Honest contract (F4): Composer and Runs do **not** share one block grammar today — Composer renders ONE joined Input block + ONE whole-workspace Output block (`composer-workstream.js` `_logBlock`/`_logChip`/`_renderLogs`); Runs renders **per-workspace-key** expandable rows with previews, char/item counts, and a 24-row cap (`runs-tab.js` `_renderStepPrompt`/`_renderStepOutputs`). The shared module owns the **common grammar** (chips, expander block primitive, escape/keying discipline) with two explicit block modes (`joined` | `per-key`); each surface keeps its native wrapper. After U7 both surfaces show the **same per-step information** (Input, Output, strategy chips) — not byte-identical markup. The Context rail (OP5) and Artifacts tab (OP3) *pivot* to `#/runs/<run_id>` for step-level drill instead of duplicating (O6e).
2. **ONE scheduler** — `api/services/schedule_service.py` + `api/routers/schedules.py` (`/api/schedules`), local-only, zero egress. Consumers: Runs (Schedules rail, dashboard, run tagging), Artifacts (Workspaces pane "Schedules operating here" + prefilled wizard via the modeled `workspace` binding field — settled in U4, not deferred), Projects (project-initiated scheduled work rides the same `seed.project_id` convention). Nobody else persists or dispatches time-based work.
3. **LibraryShell / LibraryWizard reuse everywhere** — the Library-alignment build (docs/superpowers/specs/2026-07-10-library-alignment-design.md) owns `js/library/shell.js` + `wizard.js`; **both have landed** (commit f687354) — the draft's soft-disable hedge is downgraded to a contract re-check plus cheap feature-detect. This build *consumes* their contracts and never forks them. Adapters shipped here: `schedule` (Runs rail), `artifact-output` / `workspace` / `format-set` (Artifacts tab), `context-node` (Context rail). **None of these registers `auth:'admin'`** — see the renderLock rule in Hard constraints. LibraryWizard consumers: the scheduled-run wizard (first live consumer) and the Artifacts "+ Bind Directory" flow. Exception, per judge directive: the Projects UI unit uses the **drawer grammar only** (AssetPeek slide-over pattern); its LibraryShell Docs adapter is a named follow-up.

**Judge verdict (binding, kept verbatim in spirit):** winner = **Design B (board-first)** built exactly as sliced — the only design whose every layer rides a verified primitive (tasks.jsonl append log with per-event `ts` already on disk, the three hardcoded column sites, kanban.js extension, workspace CRUD, project-side runs.jsonl so the frozen engine stays frozen) — with **Graft 1 from C** (formal `POST /api/projects/{id}/plan/apply` plan-ops contract + enclave-pm skill + pm-plan-ops role + `seed.project_id/task_id` convention + pending-proposal cap) and **Graft 2 from A** (structured docs skeleton `specs/ plans/ notes/ decisions/ index.md`, Docs sub-view with tree + markdown editor, project-scribe expand-only agent, Draft-plan flow, vault-policy encoding). B's honesty rules hold: **AI never mutates silently** (everything AI-originated lands `state:proposed` and requires operator accept), timeline renders missing dates as an explicit Unscheduled lane, run refs are labeled best-effort. **Explicitly rejected by the judge:** A's file→task checklist extraction (board stays canonical; docs are context, not a second task store); C's lifespan reconciler and column↔status remap; full LibraryShell tab rebuild in the UI unit (drawer grammar only, shell adapter late+thin).

## Hard constraints (apply to every unit)

- **Frozen engine:** `api/services/workflow_engine.py`, `api/services/step_executor.py`, `api/models/workflow_models.py` are read-only. All new persisted facts live in router/service code or sidecar files (`origin.json`, `runs.jsonl`, `schedules.json`, `dispatches.jsonl`). The one sanctioned engine seam is calling `engine.run(defn, seed, run_id=...)` and `engine._checkpoint()` exactly as the existing run-async handler already does (workflows.py:490-565) — including its `TypeError` fallback for older `engine.run` signatures (:551-555).
- **No new inline `on*=` handlers, no new window globals.** All new wiring rides the delegated `Actions.click` data-action table (main.js / `shell/actions.js`) or LibraryShell's `lib.*` grammar. New JS is ES modules imported by main.js. Pre-existing inline handlers (nav buttons, kanban, the four Runs filter chips) stay **verbatim** — they are pinned in `tests/parity/golden/inline_handlers.json` and `tests/parity/test_parity.py::test_no_handler_drift` fails on any symbol-set change.
- **ONLY ADD — never lose functionality.** Renames keep legacy remaps (the switchTab `'documents'→'research'` pattern, main.js:104-113). Element ids, API paths, JS symbols, `data-action` ids, and column vocabularies are preserved or extended additively. **One sanctioned test re-anchor** (the F1 blocker): `tests/playwright/test_kanban.py:115` asserts `.kanban-col[data-column]` count `== 3` exactly — that assertion is re-anchored to the three legacy columns **in the same commit** that adds columns (U3, detail in §3.2). No other golden or test anchor changes.
- **Parity baseline:** `tests/parity`, `tests/ui`, and the non-slow e2e 14-failure set must not regress. **No golden regeneration by any unit.**
- **renderLock rule (F5):** `AdminAuth.renderLock` replaces the **entire tab's** DOM (`getElementById('tab-' + panelId).innerHTML = …`, admin/auth.js:61-72), and `LibraryShell.guard()` calls it for `auth:'admin'` adapters (shell.js:83-90). Therefore **no adapter mounted inside a shared tab may register `auth:'admin'`**. Rail adapters (`schedule` in #tab-runs, `context-node` in #tab-context) register `auth:'optional'`; write actions carry `AdminAuth.authHeaders()` explicitly; a 401 renders a **scoped lock row inside the rail container** (reusing `.admin-lock` markup + `data-action="admin.sign-in"`, re-rendering only the rail on success) — a signed-out operator can never blank a host tab that has non-admin content. `guard()` honors `a.lockPanelId` but renderLock hard-prefixes `tab-`, so it cannot target a rail sub-container; extending renderLock to accept a raw element id is a named coordination follow-up with the library build.
- **Privacy-first:** scheduler runs in-process on the app event loop; zero network I/O in `schedule_service`; all stores are local JSON/JSONL under `data/`.
- **`require_master_key` on write routes** (middleware.py:233; no-op when `ENABLE_API_AUTH` is off): schedules writes, plan/apply + proposal accepts, project runs.jsonl POST, project context-workspace bind, format-set writes, and (hardening) the real workspace write surface (§6.3).
- **Scope parity for reads (F9):** any new read route serving bytes already scope-gated at their original route ships **with** its own SCOPE_MAP entry in the same unit — `"/api/schedules": "workflows"` (U4), `"/api/artifacts": "workflows"` and `"/api/format-sets": "workflows"` (U10). SCOPE_MAP lives at middleware.py:56-68.
- **Path containment on every id→path resolution:** `resolved.relative_to(store_root)` discipline (project_service.py:300-309, workspace.py `_resolve`); strict per-segment charset allowlists on composite artifact ids; schedule ids `^sched_[a-z0-9_]{1,64}$`; run-dir reads asserted under the engine's run root.
- **Atomic writes:** tmp file + `os.replace()` for `schedules.json`, `origin.json`, format-set files; append-only JSONL (single-line appends) for event/history logs with torn-line-tolerant reads (ralph journal pattern, engine_executors/ralph.py).
- **Route-ordering discipline (F15):** literal paths register before parameterized ones — `/summary` above `/{schedule_id}` in schedules.py; `GET /runs-index` lands **adjacent to the existing `/runs` handlers** (workflows.py:568 block), never after the `GET /{workflow_id}` catch-all at :847. Route-resolution tests assert both.

**Operate nav order — fixed once, used everywhere (F20/C10):** `Workflows · Projects · Runs · Artifacts · Context`. U1 establishes it; U11 inserts Artifacts between Runs and Context (the S4 comment block at index.html:334-337 sits immediately above the Context button and stays adjacent). No section repeats a different order.

## 3. Runs + Scheduler — O6 (a–f)

### 3.1 U4 — scheduler backend architecture (O6c backend — the un-cut BU8b follow-up)

The composer-agentic-revamp spec named this exactly: "minimal scheduler service + router (non-engine)". Built real here; every other track consumes it.

**Naming:** `api/services/scheduler.py` is TAKEN (DAG feasibility facade — verified) → new module is `api/services/schedule_service.py`; route prefix `/api/schedules` avoids `GET /api/workflows/{id}/schedule-preview` (workflows.py:882). **No new dependencies** — cadence is `interval | daily | weekly` (cron expressions are a named cut; croniter revisited on demand).

**ScheduleDefinition** (pydantic model local to the service, NOT workflow_models.py):
- `id` (`sched_<ms-hex>_<uuid4[:6]>`, collision-proof per the task-id lesson, projects.py:167 precedent), `name`, `category` (free text, datalist Research/Report/Maintenance/Task), `enabled=True`.
- `workflow_id` — validated at CRUD time via `engine.resolve_workflow_path` + `engine.validate(defn, seed_keys)` → 422.
- `seed` dict.
- **`workspace: Optional[str]` (C4 — the O5 schedule↔directory binding, settled BEFORE the schema persists):** validated at CRUD time against `get_workspace_registry()` names → 422 on unknown. At dispatch time the service resolves the workspace and injects `seed.workspace = <name>` and `seed.workspace_root = str(ws.root)` (the C2 convention — `WorkspaceMeta.root` is the absolute local path, services/workspace.py:68/82). A workspace deleted after schedule creation → journaled `error: workspace_missing`, counts toward `consecutive_failures`.
- `cadence {kind, every_seconds≥300, at: "HH:MM", weekday: 'mon'|'tue'|'wed'|'thu'|'fri'|'sat'|'sun'}` — **weekday is a named enum in the API (F7)** so neither Python's Monday=0 nor JS's Sunday=0 integer convention can leak across the wizard boundary.
- `max_consecutive_failures=5` (ralph halt-cap precedent), bookkeeping (`created_at/updated_at/last_dispatched_at/last_run_id/last_status/consecutive_failures`).

**Timezone (F7): UTC everywhere.** The engine persists `datetime.utcnow()` throughout; schedule evaluation, `at "HH:MM"`, `next_fire_at`, and all bookkeeping are UTC. The wizard and rail render the operator's **local time alongside an explicit "stored as UTC" note** (human cadence line shows both). Because no local-time math runs server-side, DST transitions cannot double- or zero-fire; skip-not-backfill covers any residual clock jump.

**Persistence:** `data/config/schedules.json` — load-all/save-all with **atomic writes** (tmp + `os.replace`); a single `asyncio.Lock` serializes router mutations against the dispatch loop.

**Dispatch journal — bounded (F8):** `data/schedules/dispatches.jsonl`, append-only, torn-line-tolerant reads (ralph journal pattern, engine_executors/ralph.py). **Transitions only:** `dispatched`, `error`, one `skipped_missed` per missed window, and overlap **episodes** — one `skipped_overlap_start` when an overlap begins and one `skipped_overlap_end {ticks_skipped: N}` when it clears (never one line per 30s tick). **Size-capped rotation on the api.log pattern** (RotatingFileHandler semantics, logging_config.py:51-53): on append, if the file exceeds 5 MB it rotates to `dispatches.jsonl.1` (single backup, older discarded). History reads are a bounded reverse tail of the current file (+ `.1` when the tail underruns).

**Dispatch path — `api/services/run_dispatch.py` (F2/C5 — expresses BOTH run-async branches):**

```
prepare_run(*, workflow_id: str | None = None,
             definition: dict | None = None,
             seed: dict, origin: dict) -> (defn, run_id)
```

- `definition` → `engine.load_from_dict(definition)` (the branch the Composer's Run ▶ live path depends on — main.js builds `{definition, seed}` via `dfBuildWorkflowDefinition`, ~:10196-10210); `workflow_id` → `engine.resolve_workflow_path` + `engine.load`; neither → error the handler maps to 400.
- Then, both branches identically: `engine.validate` (handler maps `WorkflowValidationError` → 422) → uuid4 `run_id` → queued-placeholder `engine._checkpoint` (try/except pass, as today) → atomic **origin sidecar** `data/workflows/<run_id>/origin.json`.
- `dispatch_blocking(defn, seed, run_id)` — `engine.run(defn, seed=seed, run_id=run_id)` **with the existing `TypeError` fallback preserved verbatim** (workflows.py:551-555).
- The run-async handler is refactored onto `prepare_run(workflow_id=req.workflow_id, definition=req.definition, seed=req.seed, origin={"origin":"manual"})` + BackgroundTasks, with a **byte-identical response contract** `{run_id, workflow_id, status:"queued", poll_url}` — the only new observable is the sidecar. Regression tests cover **both** branches, including a definition-based POST asserting the contract and origin.json.
- In-process dispatch deliberately bypasses HTTP auth middleware (it only wraps HTTP); this is why the loop calls the engine directly rather than loopback-POSTing with a stored key. Privacy: no network I/O anywhere.

**Dispatch loop:** started in `api/main.py lifespan()` (:93) after `bind_loop` (:240), before `yield`, wrapped in try/except with a degraded-mode warning (never-block-boot convention); cancelled + gathered after yield. Semantics:

- 30s tick (`SCHEDULER_TICK_SECONDS`); **missed windows skipped, never backfilled** (journaled `skipped_missed`).
- **Double-fire hardening (F6):** `last_dispatched_at` is persisted atomically (lock-held, tmp+replace) **before** the run is handed to the executor — the same critical section that appends the `dispatched` journal line. Completion-time writes update only `last_status`/`last_run_id`/`consecutive_failures`. **Boot reconcile:** before the first tick, the tail of dispatches.jsonl is read; any `dispatched` entry without a terminal run.json is re-checked — still running → adopted as in-flight for overlap purposes; vanished/failed → counted as a failure. A restart mid-dispatch can therefore never re-fire the same window.
- **Overlap guard with zombie takeover (F17):** previous dispatch counts as running only when its run.json is `running|queued` **and** its newest timestamp is within `SCHEDULER_ZOMBIE_MINUTES` (default 120). The engine's boot-time stale-run reaper (workflow_engine.py:240-286, runs once per process boot) already flips crashed runs after a restart; this cap covers the no-restart case. On takeover: journal `overlap_takeover`, treat as not-running, and surface the schedule as **degraded** in `/summary` (repeated-overlap count is a distinct health signal there) — a stuck run can no longer stall a schedule forever while it "appears enabled".
- **Executor (F14):** `asyncio.to_thread` accepts no executor argument — dispatch goes through `loop.run_in_executor(_SCHED_POOL, functools.partial(dispatch_blocking, …))` where `_SCHED_POOL` is a module-owned `ThreadPoolExecutor(max_workers=SCHEDULER_MAX_CONCURRENT)` (default 2), shut down in lifespan teardown. Blocking `engine.run` never touches the loop's default pool, so it cannot starve other `to_thread` users.
- **Multi-process guard (F16):** the loop assumes a **single worker** (documented in the module docstring and deployment docs — `uvicorn --reload`/`--workers>1` would otherwise run one loop per process). Best-effort `O_EXCL` lockfile `data/schedules/scheduler.lock` (pid + boot ts): a second process's loop logs a warning and no-ops (CRUD routes still work everywhere; only the loop is exclusive); a stale lock owned by a dead pid is reclaimed.
- On thread completion: read final run.json status → update `last_status`, increment/reset `consecutive_failures`, auto-disable at cap with journaled error; every transition appends to the journal and persists bookkeeping atomically.

**Router `api/routers/schedules.py` — literal routes FIRST (F15/C6):** `GET /summary` (dashboard payload: enabled count, 24h dispatched/skipped/failed, repeated-overlap flags, next-5 upcoming) registered **before** `GET /{schedule_id}`; then `GET ""` (list + computed `next_fire_at`), `GET /{id}` (+ last 10 history), `GET /{id}/history?limit=50` (bounded reverse tail). Reads scope-authed via new SCOPE_MAP entry `"/api/schedules": "workflows"`. Writes all `Depends(require_master_key)`: `POST ""` (422 on validation failure, incl. unknown workspace), `PUT /{id}` (re-validates, resets failure counter on cadence/workflow change), `DELETE /{id}` (history JSONL retained — audit trail), `POST /{id}/enable|/disable`, `POST /{id}/run-now` (immediate prepare+dispatch, `trigger:"run-now"`, returns `{run_id, poll_url}`, does NOT shift the cadence clock or count toward auto-disable). Registered in the main.py include_router block. A route-resolution test asserts `/summary` returns the dashboard shape (not a 404 from the id handler).
