# EfficientIP DDI -- representative redacted syslog samples
#
# Captured during Task #86 (RFC 3164 envelope) and Task #89
# (RFC 5424-in-kernel envelope) from the user's production
# corpus. The appliance ships syslog in two envelope shapes:
#
#   1. RFC 3164:           <PRI>MMM DD HH:MM:SS [HOST] daemon[PID]: BODY
#   2. RFC 5424-in-kernel: <PRI>MMM DD HH:MM:SS kernel: ISO_TS HOST daemon PID - - BODY
#      (the appliance forwards a minimal RFC 5424 record wrapped
#      inside an RFC 3164 envelope; the two `- -` tokens are the
#      RFC 5424 NILVALUE placeholders for MSGID and STRUCTURED-DATA)
#
# EfficientIP appliances usually omit the syslog hostname in the
# RFC 3164 shape (15 of 16 production samples have no host token
# between the timestamp and daemon[pid]:); the kernel-wrapped
# shape always carries a hostname inside the inner RFC 5424
# record. The shared header rule handles both shapes and silently
# nulls when a token is absent.
#
# Each daemon (named, dhcpd, sshd, sudo) emits its own wire format.
# The four stanzas in the rule cover them in order. devd[],
# ipmserver[], and unwrapped kernel: ipfw lines are appliance-
# internal noise and are dropped by the allow-list filter at the
# head of the shared header rule before they reach any stanza body.
