# `field_anchors.json` -- schema reference

Companion document to `PRIVATE_DOCS/field_anchors.json`, generated by
`scripts/extract-field-anchors.ts` (Task #33). This file is the canonical
description of the JSON shape; the JSON itself carries a `schema` field
that points back here.

## Top-level object

| Key              | Type   | Description                                                                                                                                            |
| ---------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `schema_version` | string | Currently `"1"`. Bumped only on a breaking change to the anchor object shape.                                                                          |
| `generated`      | string | ISO-8601 UTC timestamp of the most recent extractor run.                                                                                               |
| `source_corpus`  | string | Path to the rule corpus the extractor read.                                                                                                            |
| `rule_count`     | int    | Number of distinct rule blocks parsed from the corpus.                                                                                                 |
| `anchor_count`   | int    | Number of distinct `xdm.*` paths that received at least one synonym (== number of keys under `anchors`).                                               |
| `notes`          | string | Human-readable summary of the normalisation rules.                                                                                                     |
| `schema`         | object | Self-describing schema metadata; mirrors this file in short form.                                                                                      |
| `anchors`        | object | The actual data, keyed by canonical `xdm.*` path. See below.                                                                                           |

## `anchors[xdm.path]`

| Key              | Type     | Description                                                                                                                                                                                                                                          |
| ---------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `frequency`      | int      | Number of distinct rule blocks that contain at least one assignment to this `xdm.*` path. This is the value the modelfile inclusion threshold (`>= 3`) is gated on.                                                                                  |
| `synonyms`       | array    | Vendor source-field synonyms that resolved to this path, deduplicated and normalised. Sorted by descending `count` then alphabetic by `synonym`. Each element has `{synonym: string, count: int}`.                                                   |
| `synonyms_simple`| string[] | Compatibility projection: the same synonyms as `synonyms`, in the same order, but reduced to bare strings. Matches the shape called for in the original Task #33 brief.                                                                            |
| `exampleVendors` | string[] | Up to 12 distinct vendor identifiers (taken from rule `[MODEL: dataset=...]` / `[INGEST: vendor=...]` headers) observed mapping to this path. Useful for spot-checking that an anchor genuinely cuts across vendors rather than being vendor-locked. |

## Synonym normalisation

Performed by `normaliseSynonym(raw)` in `scripts/extract-field-anchors.ts`:

1. Trim and lowercase.
2. Strip a leading `@` (JSON-path artefact, e.g. `$['@severity']`).
3. Replace runs of `.`, `-`, or whitespace with `_`.
4. Strip leading underscores.
5. Strip a single `tmp_` prefix.
6. Collapse runs of underscores; trim trailing underscores.

So `Src.IP`, `src-ip`, `_src_ip`, and `_tmp_src_ip` all collapse to
`src_ip`.

## Note on shape vs. the original brief

The Task #33 brief described `synonyms` as a bare `string[]`. The
implementation keeps the richer `[{synonym, count}]` shape because every
downstream consumer (linter ranking, IDE quick-fix confidence scores,
the regression-suite ordering check) needs the per-synonym frequency.

To recover the brief's simple shape:

```ts
const simple = Object.fromEntries(
  Object.entries(json.anchors).map(([k, v]) => [
    k,
    v.synonyms.map((s) => s.synonym),
  ]),
);
```

## Reverse lookup (synonym -> xdm path)

The forward shape is xdm-path-keyed, so reverse lookup needs an inverted
index. Build it once at startup:

```ts
import { readFileSync } from "fs";
import { normaliseSynonym } from "../scripts/extract-field-anchors.js";

interface AnchorEntry {
  frequency: number;
  synonyms: { synonym: string; count: number }[];
}
type AnchorJson = { anchors: Record<string, AnchorEntry> };

const json: AnchorJson = JSON.parse(
  readFileSync("PRIVATE_DOCS/field_anchors.json", "utf8"),
);

// synonym (normalised) -> ranked candidates [{ xdmPath, score }]
const reverse = new Map<string, { xdmPath: string; score: number }[]>();
for (const [xdmPath, entry] of Object.entries(json.anchors)) {
  for (const s of entry.synonyms) {
    const key = normaliseSynonym(s.synonym);
    const list = reverse.get(key) ?? [];
    // Score combines per-synonym count with anchor frequency.
    list.push({ xdmPath, score: s.count * entry.frequency });
    reverse.set(key, list);
  }
}
for (const list of reverse.values()) list.sort((a, b) => b.score - a.score);

// Lookup: pass the raw vendor field name, get ranked xdm.* candidates.
function lookup(field: string): { xdmPath: string; score: number }[] {
  return reverse.get(normaliseSynonym(field)) ?? [];
}

lookup("Src.IP");        // -> [{ xdmPath: "xdm.source.ipv4", score: ... }, ...]
lookup("dpt");           // -> [{ xdmPath: "xdm.target.port", ... }, ...]
lookup("CefSeverity");   // -> [{ xdmPath: "xdm.alert.severity", ... }, ...]
```

Always normalise the input through `normaliseSynonym` so callers are not
sensitive to case, whitespace, or `.`/`-` punctuation.

## Regenerating

```sh
# One command runs the extractor and the regression suite end-to-end.
bash scripts/run-anchor-tests.sh

# Or invoke them individually:
npx tsx scripts/extract-field-anchors.ts
npx tsx scripts/check-field-anchors-regressions.ts
```

The extractor is idempotent: it rewrites `Section 12` of the offline
modelfile in place (preserving any sections that come after) and emits a
fresh `field_anchors.json`.
