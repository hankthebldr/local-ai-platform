RELEASE NOTES
A

Architecture-aware dispatch

Detection
Per-host detection of memory topology (unified / single-GPU / multi-GPU) and deployment shape (DMG / Container / HostNative). Pluggable Architecture + Deployment protocols.
Dispatch
Tick-based parallel DAG dispatcher: each tick asks the detected arch which steps to run concurrently vs defer. Falls back to single-step-per-tick on workflows without depends_on.
B

Per-step keep_alive + telemetry

Resolution
Four-tier resolver: step config > workflow default > arch-detected default > OLLAMA_KEEP_ALIVE. Defaults are 30m on CPU (reload dominates), 0 on single-GPU NVIDIA (VRAM is scarce).
Observability
Ollama load / prompt-eval / eval durations captured per workflow step. Live snapshot at /api/system/architecture.
C

Installable Python package

Surface
Wheel + sdist attached to every release. Console scripts enclave, enclave-api, enclave-chat, enclave-workflow.
Install
pip install <wheel-url> — no PyPI account required.
D

GHCR mirror, tarball, n8n

Container
Every Docker Hub push mirrored to ghcr.io/hankthebldr/enclave. Linux source tarball with SHA-256 + SHA-512 sidecars on every stable release.
Automation
Importable n8n workflow under workflows/n8n/ drives release prep through a local Ollama instance — no cloud LLM calls.

THE COMPOSER

A workflow is crystallized conversation.

CHAT → SPEC → DAG

Most agent builders hand you an empty canvas and a node palette. The Composer starts where the work actually starts — you talking to a local model about a problem — and turns that thread into something repeatable. Authoring happens before execution: nothing here touches the workflow engine, and nothing leaves the machine.

01

Boot Sequence

Synopsis
POST /api/composer/capture-spec
Description
Reads the whole thread and distills the durable intent into a structured spec: a goal, the inputs a future run needs, and the checks that define done-well. It generalizes lightly so the result is reusable, and it is instructed not to invent requirements you never implied.
Where it runs
On a local model you already have installed. No cloud, no telemetry.
02

Review the plan card

Contract
The spec is yours to edit before anything is built — rewrite the goal, add an input, tighten a check.
Why it exists
A distilled spec is a guess about your intent. Making it editable is cheaper than debugging a fifteen-node DAG that guessed wrong.
03

Scaffold, three tiers

Synopsis
POST /api/composer/scaffold
Resolution order
A template match against the curated workflow index wins when the spec scores well — reusing a workflow that already runs beats generating a new one. Otherwise a local model composes a fresh chain bound to your installed roles and agents. If the model is down or returns junk, a deterministic intake → work → validate chain is synthesized so the canvas always primes.
Honesty
The response carries source — template, llm or fallback — plus the matched workflow id and the role bindings. You always know which tier produced the thing on your canvas.
04

Bound to what you have

Primitives
Generated steps bind to locally installed roles and agents, each labelled with the local model it will run on — so the canvas shows who handles what, on which model, before a single token is spent.
No phantom steps
The planner composes from the inventory you actually have, not a catalog of things you would need to go install.
05

Node-bound chat

Description
Select a node and the chat pane rebinds to that step — talk to that agent, configure it, rate its output. Ratings feed per-agent tuning, so the surface you debug in is the surface you improve in.
06

Drafts that survive

Synopsis
GET|POST|DELETE /api/composer/drafts
Description
Canvas snapshots persist on the box, so a half-authored workflow is still there after a restart. A run started from an unsaved canvas keeps its originating definition beside the run, which is what makes fix-and-resume possible later.

Pre-execution authoring only. capture-spec and scaffold never import the workflow engine — they emit the same WorkflowDefinition the Composer already loads, so an authored workflow and a hand-written one are the same artifact by the time they run.

OpenAI-compatible

CPU-first inference

Backend
Ollama + GGUF (Q4_K_M default, Q5_K_M for quality, Q3_K_M for 70B+).
Throughput
7B ≈40-50 t/s · 13B ≈25-30 t/s · 34B ≈10-15 t/s on commodity x86.
03

Zero telemetry

Network
No outbound calls except model pulls you initiate. No analytics, no crash reports, no phone-home.
Audit
Source-available. Read the egress paths yourself.
04

Multi-agent workflows

Engine
Jinja2 prompts, output parsers, quality gates, checkpoint/resume, six-phase hook lifecycle.

First launch — gatekeeper note

The DMG ships unsigned today. After dragging to /Applications, run once to clear the quarantine flag:

xattr -dr com.apple.quarantine /Applications/Enclave.app

Then launch Enclave — the native window opens the first-run wizard, which installs Ollama and pulls a starter model.
